Sources: google/talkback @229212fdf5842191d0a93fc95d9ca1423b346866 (TfPu_release_16_2; the emulator runs 17.0.0, which is closed source); Compose ui 1.12.1/1.11.1 src + 1.7.0/1.8.2 javap; AOSP frameworks/base main (2026-09-30). Research copies of these sources lived in the audit scratch (not in the repo).
UT = utils/src/main/java/com/google/android/accessibility/utils/ ; TB = talkback/src/main/java/com/google/android/accessibility/talkback/ ; D = Compose AndroidComposeViewAccessibilityDelegateCompat.android.kt (1.12.1). SV = source-verified, AS = assumed.

## Part 1: TalkBack's real rules
### (a) Which nodes get focus: shouldFocusNode (UT/AccessibilityNodeInfoUtils.java:838), in order [SV]
1 web content: delegate to the WebView (focus only if the container is visible). 2 !isVisible (isVisibleToUser, :2364) → skip. 3 PiP → focus. 4 bounds == window bounds && has children && !focusable/clickable → skip (areBoundsIdenticalToWindow :2428; the full-window wrapper rule). 5 "a11y-focusable" = isFocusableOrClickable (:1908: visible && (screenReaderFocusable || isActionableForAccessibility)) || (isTopLevelScrollItem && isSpeakingNode). isActionableForAccessibility (:1159) = clickable || long-clickable || focusable || ACTION_FOCUS (input focus). ACTION_ACCESSIBILITY_FOCUS does NOT count (Compose adds it to every node, D:694). 6 if a11y-focusable: a LEAF (childCount 0) is ALWAYS focused (the unlabeled-button path); otherwise only if isSpeakingNode, else "focusable but nothing to speak" → a clickable container whose children are all focusable is skipped and each child is a stop. 7 otherwise: focus only if NO a11y-focusable ancestor (checkChildren=false) AND (hasText || hasStateDescription).
- isSpeakingNode (:1001) = hasText (:1879: text/contentDescription/hintText; FALSE for any node with CollectionInfo) || hasStateDescription (:1893: stateDescription/checkable/valid RangeInfo) || hasNonActionableSpeakingChildren (:1045: any visible child that is not focusable/clickable and is speaking, recursively; a speaking top-level scroll item under a non-clickable parent is ignored; an INVISIBLE non-actionable child with text also counts (:1109) unless the node itself passes FILTER_AUTO_SCROLL → a ghost-stop source).
- isTopLevelScrollItem (:1920) = visible && parent is scrollable (any SCROLL_* action) or Role LIST/GRID/SCROLL_VIEW/HORIZONTAL_SCROLL_VIEW (Spinner excluded).
- Role (UT/Role.java:772) is class-based: ImageView→IMAGE (IMAGE_BUTTON if clickable); Switch, ToggleButton, RadioButton, CompoundButton→CHECK_BOX, Button, CheckedTextView, EditText, SeekBar (or RangeInfo+SET_PROGRESS), ProgressBar, WebView, TabWidget, HorizontalScrollView (only without CollectionInfo), ScrollView, ViewPager, NumberPicker, Spinner, GridView, AbsListView; then any PAGE_* action→PAGER; then any CollectionInfo→LIST (GRID if rows>1 && cols>1); ViewGroup→VIEW_GROUP.
- Importance [SV]: TalkBack does NOT request flagIncludeNotImportantViews (res/xml-v33/accessibilityservice.xml), so it sees only important Views; non-important Views are flattened (children hoisted in place). AOSP ViewGroup.addChildrenForAccessibility (:2477) adds only VISIBLE children (INVISIBLE/GONE absent), sorts siblings with ChildListForAccessibility STRIPE (:9185-9235), and recurses into children that aren't included. View.isImportantForAccessibility (View.java:15687): false for NO/NO_HIDE_DESCENDANTS or when any ancestor is NO_HIDE_DESCENDANTS; else YES || actionable || has listeners || has a provider/delegate || live region || pane || heading.
- **OUR AGENT SEES MORE THAN TALKBACK**: query-from-app-process uses DirectAccessibilityConnection with FETCH_FLAGS = REPORT_VIEW_IDS | INCLUDE_NOT_IMPORTANT_VIEWS (AOSP DirectAccessibilityConnection.java:57) [SV]. The static model MUST project the dump down to TalkBack's view.
- Visibility [SV]: View.isVisibleToUser (View.java:11711) = attached && visible window && every ancestor VISIBLE with alpha>0 and transitionAlpha>0 && non-empty getGlobalVisibleRect (fully clipped/offscreen = invisible; a node OCCLUDED by a sibling/overlay is STILL visible). Compose: isVisibleToUser = not hidden (alpha 0 in the chain, hideFromAccessibility, invisibleToUser); nodes covered by *important* later siblings, and zero-size/offscreen nodes, are REMOVED from the tree (SemanticsOwner uncovered map); a non-semantic scrim covers nothing.
- Compose focusability [SV]: isScreenReaderFocusable (D:3446) = !hidden && (merging || an unmerged leaf that speaks via contentDescription/text/stateDescription/checkable). isFocusable = the Focused property is present (every clickable). isImportantForAccessibility = !hidden && (merging || has an a11y property). Fake nodes: a merging node with children AND a contentDescription gets NO contentDescription itself; a fake first child (id+2e9) carries it (D:733). A Role's className goes on a fake child (id+1e9) instead of the parent (D:631), so Button{Text} has parent class android.view.View.
- Containers vs children: a focusable container is a stop exactly when it speaks via non-focusable descendants; focusable children are separate stops (the DOUBLE-STOP mechanism).

### (b) Linear order [SV]
Entry: gesture (TB/gesture/GestureController.java:265-288) and keys (TB/keyboard/KeyComboMapper.java:183-201) → FocusProcessorForLogicalNavigation.navigateToDefaultOrMacroGranularityTarget (:1105) with scroll=wrap=true. Pivot (:347; AccessibilityFocusMonitor:100) = findFocus(FOCUS_ACCESSIBILITY) if visible, else input focus, else the ROOT of the active window ("next" goes to the top). So when a focused node scrolls off, the next swipe restarts at the top.
Per step the order is rebuilt from the pivot's window root (TraversalStrategyUtils:73 → OrderedTraversalStrategy → UT/traversal/OrderedTraversalController.initOrder):
1 A WorkingTree mirrors the ANI tree. Children come via ReorderedChildrenIterator: ANI order, EXCEPT that a child failing shouldFocusNode gets "effective bounds" (the union of its focusable descendants' bounds, clipped to its own; NodeCachedBoundsCalculator.fetchBound) and moves later among siblings when a STRIPE-like compare on effective bounds says to swap AND the real bounds agree with the original order (needSwapNodeOrder). This reordering exists ONLY in TalkBack.
2 reorderTree visits every node in pre-order: if getTraversalBefore() resolves → moveNodeBefore(node, target): the node's subtree is lifted to any ancestor whose own traversalBefore is this node (getParentsThatAreMovedBeforeOrSameNode); it REPLACES the target in the target's parent's list, and the target becomes the LAST CHILD of the node. No-op if the target is a descendant or the move would create a loop. Else if getTraversalAfter() resolves → the node's subtree becomes the LAST CHILD of the target. Before wins over after; unresolvable targets are ignored. The requestInitialAccessibilityFocus node is recorded; the FAB-first flag is used only for initial focus.
3 Next = pre-order successor (WorkingTree.getNext); Previous = the last descendant of the previous sibling, else the parent.
4 searchFocus (TraversalStrategyUtils:351) steps until shouldFocusNode accepts. A repeated node → "Found duplicate during traversal" → null (treated like an edge).
Consequence: a Compose chain a→b→c (traversalBefore = the next) ends up at the tree position of its LAST member, in chain order. Compose order fully overrides tree order inside one AndroidComposeView. It never crosses ComposeViews or windows. improve/a11y-core's reading_order is a DIFFERENT approximation (processing order, the subtree lift, target-becomes-child, bounds reordering, importance flattening, the window-wrapper rule, invisible-text-children, CollectionInfo nodes "having no text").
Compose publication [SV]: setTraversalValues (1.12.1/1.8.2 static helper; 1.7 private instance) collects screen-reader-focusable nodes + traversal groups; sortByGeometryGroupings (SemanticsSort.kt:100-160) groups rows by vertical overlap (the row cover shrinks to the intersection), rows top→bottom, within a row left→right then top (RTL right) then z/placement order then id; a STABLE sort by traversalIndex over the WHOLE level (not per row); groups expand in place. Every linked node gets setTraversalBefore(next). setTraversalAfter only after an interop View (D:1144-1178). ANI children are NEVER reordered (placement order); 1.13.0-alpha01 starts sorting children of merging traversal groups. The maps are computed only while isEnabled (AccessibilityManager.isEnabled && a non-empty service list); the agent primes them with ComposeTraversal.prime. LazyColumn/LazyRow/grids/pagers are traversal groups (foundation LazyLayoutSemantics.kt:181).
Views [SV]: setAccessibilityTraversalBefore/After(id) resolves inside-out (View.java:11440-11462 findViewInsideOutShouldExist); the link is DROPPED if the target is not includeForAccessibility.
Hybrid [SV]: between Views, the STRIPE sort (non-overlapping rows first; then left, top, taller, wider). An AndroidView holder is a merging semantics node in the chain, added via info.addChild(holder); its delegate marks the holder invisible ONLY while a service is on → dumps taken with TalkBack on vs off DIFFER.
Windows [SV]: search stays in the pivot's window; with no target there, findTargetAcrossWindows (:1620). Windows are sorted GEOMETRICALLY, not by z (TB/focusmanagement/WindowTraversal.java:52-112): displayId, TYPE_SYSTEM last, then top, then left (RTL right). The window filter (:3271-3313) accepts app windows, the IME, and system non-bar windows. At the last window the first press only sets reachEdge (no move/speech); the second wraps to the first window (WindowTraversal:193). AOSP AccessibilityWindowManager drops windows fully covered by touchable regions → a touch-modal Dialog window hides the activity behind it [SV the drop; AS that a Dialog's touchable region spans the task]. Same-window overlays stay fully reachable; a non-modal popup is read AFTER the main window content when it sits lower (geometric sort).
Edges/auto-scroll [SV]: autoScrollAtEdge (:2264) runs BEFORE the search. The scrollable must be the nearest self/ancestor passing FILTER_AUTO_SCROLL (UT:458: a scroll action, visible, Role LIST/GRID/SCROLL_VIEW/HSV/Spinner; **PAGERS EXCLUDED**) and support the direction's action (FORWARD, else DOWN/RIGHT/LEFT by axis; ScrollableNodeInfo:104,177). "At the edge" = the next focusable is null, is the scrollable itself, or is outside it (TraversalStrategyUtils:229,267). After scrolling, wait ≤1000ms for TYPE_VIEW_SCROLLED from that node (API 28+: scrolled ≥60% of the container or reached the edge; AutoScrollSuccessCheckerImpl:66). Success → search again from the old focus (up to 100×); if the old focus was recycled → the container's first/last focusable. performAction false → focus leaves the list. True but no scroll event → the container becomes the pivot with descendants ignored → **THE REST OF THE LIST IS SKIPPED** (:2906). Compose: a scrollable without CollectionInfo gets className ScrollView "so auto scroll works" (D:1048); LazyColumn has CollectionInfo (rows = item count) → LIST; no CollectionItemInfo on lazy items; SHOW_ON_SCREEN is handled but never advertised.

### (c) Spoken text [SV]
TB/compositor/rule/EventTypeViewAccessibilityFocusedFeedbackRule.java:181 = name block + collection position ("3 of 20" / "Row 2, Column 3" with heading) else "Heading" + collection transition ("In list, 20 items"/"Out of list") else the container title ("In X") + "Window <title>" on a window change. The name block (roledescription/TreeNodesDescription.java:100-343) = "selected" + tree + "disabled"/"read only". Tree = error, hint (dropped for an EditText with text), STATE NAME ROLE (the default order; res donottranslate.xml:1242), children, tooltip, then "for <labels>" (labelledBy). NAME = contentDescription ELSE text (never both); ROLE from the class (ViewGroup/TextView → no role word). Children are appended ONLY when the focused node has NO contentDescription (or its role is list/grid/pager), counting only visible, non-a11y-focusable children, recursively → **A CONTENTDESCRIPTION ON A VIEW CONTAINER SILENCES ITS CHILDREN**. (Not on Compose: the fake cd child is spoken AND the other children too.) Checkable: "checked"/"not checked" is added only if there's NO stateDescription AND (a selection-mode collection OR checked) (TreeNodesDescription:261-269) → an UNCHECKED checkable without stateDescription says no state. View CompoundButton sets a stateDescription (API 30+) [AS]; Compose sets one only for Switch/Indeterminate/Selected (D:3501-3525) → an unchecked Compose Checkbox is announced without "not checked" in 16.2 (verify on 17.0). "Unlabelled" only for an enabled clickable/long-clickable/(focusable with a resource id) node with NO children and no text/cd/state/hint/labelledBy → the role word if any, else "Unlabelled" (AccessibilityNodeFeedbackUtils:300). "disabled" for any !enabled node except headings. supplementalDescription is not spoken in 16.2 (hard-coded "", AccessibilityNodeFeedbackUtils:174). Hints ("Double-tap to activate") come +400ms and are separate (ProcessorAccessibilityHints:61). VERBOSE logging logs every fragment: `talkback: SpeechControllerImpl … Speaking fragment text="…"` (SpeechControllerImpl:2039).

### (d) Granularities [SV]
NavigationTarget.createNodeFilter (TB/focusmanagement/NavigationTarget.java:300) = shouldFocusNode AND: Heading: isHeading() or a focusable node containing a non-focusable heading leaf (UT:273). Control: role Button/ImageButton/EditText/CheckBox/Radio/Toggle/Switch/Spinner/SeekBar/FAB, or clickable/long-clickable whose parent is NOT a List/Grid, or a visible non-focusable matching descendant (UT:317,374) → clickable list rows are NOT controls. Link: a ClickableSpan. Container: a change of nearest container (List/Grid/Pager/ScrollView/HSV/WebView/containerTitle). Window: pane-aware. At the edge: "No next heading". Enhanced keymap: browse-mode single letters (H/F).

### (e) Window changes, removal, restoration [SV]
Window changed (UT/input/WindowEventInterpreter) = a main-window id or title change; a pane counts only with a paneTitle. Delay 550ms (200 without animations, 150 for popups). The title is spoken, then the initial-focus chain (TB/focusmanagement/FocusFeedbackMapper.java:61-86): restore from the per-window record → follow input focus (edit fields) → the requestInitialAccessibilityFocus node (Compose never sets it) → the first stop whose text isn't the window title. Skipped if the user already navigated, or a11y focus is already on a visible node in the active window.
Removal: AOSP ViewRootImpl.handleWindowContentChangedEvent (:11049) CLEARS a virtual view's focus on the next SUBTREE change once the provider returns null for it. A View's focus clears on GONE/INVISIBLE/zero-size/not-important (View.java:15595/18558/18590/25820) and in removeViewInternal/removeDetachedView (ViewGroup:5609/5892). [AS] It is NOT cleared on RecyclerView detach-to-scrap-and-rebind → focus "drifts" (the same View now shows other content).
Recovery: TalkBack ignores FOCUS_CLEARED; it runs ENSURE_ON_SCREEN 150ms after a SUBTREE change or after 3s idle (TB/actor/FocusManagerInternal.java:215-264), only if NO a11y focus exists anywhere. Fallbacks: the last record by uniqueId → the same node if NOT inside a collection → NodePathDescription fuzzy match (class/id/text/neighbours/row/col) → input focus → the initial node → the first focusable ("jumps to top"). Anti-loop: it won't refocus twice from ENSURE until a touch-interaction start (key-driven walks never re-arm).
History: 5 records + an LRU of 10 windows keyed by (windowId, title, paneTitle). Only TalkBack's own focus moves are recorded. Back to the same window id+title → restore. A recreated activity, or single-activity nav without a title/paneTitle change → no restore → top.
Input focus: TYPE_VIEW_FOCUSED pulls a11y focus to that node (TB/interpreters/InputFocusInterpreter.java:111-226) unless it's a list/grid → FocusRequester.requestFocus() steals a11y focus.
Versions: 16.1 dropped the classic keymap; 16.2+ defaults to the enhanced keymap (TalkBack key = Meta); the 17.0 notes add keyboard hints and "focus starts where you left off" on touch→keyboard. Compose 1.5 traversalIndex/isTraversalGroup; 1.8 hideFromAccessibility; 1.11 offscreen children of partially visible merging nodes (marked invisible); 1.12 hidden check in isScreenReaderFocusable; 1.13-alpha child sort.

## Part 2: Error taxonomy (C = Compose, V = View, H = hybrid; Static = capture-time model; Dynamic = live walk)
- **tb.skipped**: content never reached/spoken. C: clearAndSetSemantics on a container; hideFromAccessibility/alpha 0 on an ancestor; covered by an important sibling (removed from the tree); a custom-drag scroller with no ScrollBy (offscreen items absent). V: noHideDescendants (incl. the folklore "fix" on ComposeView cells); an INVISIBLE parent; a custom scroller without SCROLL actions (clipped children invisible, never auto-scrolled); a scroller role not LIST/GRID/SCROLL_VIEW/HSV. Both: auto-scroll returns true but no TYPE_VIEW_SCROLLED within 1s (translation "scrolling") → the rest is skipped; a traversal duplicate = an edge. Static: "orphan speech" (important visible text that is neither a stop nor in any stop's announcement); facet mismatch (the View/semantics facet has text the a11y tree lacks; name the hiding ancestor). Dynamic: walk to the end with auto-scroll; predicted stops / CollectionInfo counts never visited; a 1s stall on a scroll step. Fix: remove the hiding flags or fold into a label; RecyclerView/LazyColumn or proper scroll semantics+class; dispatch scroll events.
- **tb.double_stop**: a container and a child both stop with overlapping speech. C: Card(onClick)/clickable Row + Checkbox/Switch/IconButton with its own handler; a semantics{cd} Box plus an Icon with the same cd. V: clickable row + clickable CheckBox; focusable=true TextView inside a clickable card. Static: consecutive stops, bounds contain the other, announcements overlap (token Jaccard ≥0.6) or both have the same CLICK/toggle. Fix C: Modifier.toggleable(role=Checkbox) on the Row + onCheckedChange=null; secondary actions → customActions. V: clickable/focusable=false on the child.
- **tb.ghost_stop**: unlabeled/invisible/tiny/offscreen/occluded stop. C: a clickable Box/Icon with no label (a leaf → always a stop: "Button"/"Unlabelled"); a node under a non-semantic scrim. V: a View behind a same-window overlay (occlusion doesn't clear isVisibleToUser); alpha 0.01; a clickable full-screen scrim without a label; a focusable container whose text children are all INVISIBLE (UT:1109). Static: empty/"Unlabelled" announcement; area <1dp² or outside the window; render facet occluded_full/transparent (until then, geometric same-window occlusion). Dynamic: TalkBack lands there. Fix: labels; hide the background while an overlay is open (V noHideDescendants / C hideFromAccessibility or clearAndSetSemantics{}); GONE not alpha; the scrim importantForAccessibility=no.
- **tb.out_of_order**: C: two columns with vertically overlapping rows read zig-zag without isTraversalGroup per column; traversalIndex sorted over the whole level; stacked Box offsets; RTL. V: STRIPE ignores XML order; traversalBefore/After to a duplicated id (inside-out picks the nearest) or to a non-important view (dropped); TalkBack's ReorderedChildrenIterator swaps non-focusable wrappers. Static: predicted vs heuristic visual order → inversions (stops outside the longest increasing subsequence; backward vertical jumps > half a row not explained by a column change; column interleave). Dynamic: the walk vs both. Fix: isTraversalGroup on columns/cards; traversalIndex within a group; View accessibilityTraversalAfter/Before with unique important targets; restructure.
- **tb.loop / tb.trap / tb.cycle**: V: before/after cycles (WorkingTree no-ops; searchFocus duplicate → edge). C: FocusRequester.requestFocus() in a re-running LaunchedEffect pulls a11y focus back via input-focus sync (InputFocusInterpreter); infinite "load more"; an auto-advancing pager. Static: Tarjan over traversal edges; links into ancestors; nodes with input focus + LaunchedEffect/FocusRequester in the slot facet (heuristic). Dynamic: a key repeats before an edge/wrap; focus snaps back after an app TYPE_VIEW_FOCUSED (event tap). Fix: break cycles; request focus once; "load more" as a button.
- **tb.focus_lost / tb.focus_reset / tb.focus_drift**: C: a lazy item re-created (key changed / no stable keys / AnimatedContent / key(gen)) → a new semanticsId → SUBTREE → ViewRootImpl clears → TalkBack ENSURE restores via NodePathDescription or goes to the top; lazy slot reuse re-mints ids; a ComposeView cell disposed on detach. V: notifyDataSetChanged (rebound Views: focus stays on a View now showing a different item = DRIFT); the default ItemAnimator change animation (new holder, old View removed, focus cleared); setAdapter again; Fragment replace. Static: the capture diff shows the focused ref became rebound/new (C5 rebound_of); no uniqueId. Dynamic REQUIRED: tb_scenario survive (kept/drifted/restored/reset_top/lost). Fix: stable keys (items(key=), setHasStableIds, DiffUtil with payloads, supportsChangeAnimations=false); ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed for ComposeView cells; AccessibilityNodeInfo.setUniqueId (API 33; TalkBack tries it FIRST, FocusActionRecord:150).
- **tb.escape**: focus leaves a dialog/sheet/pane. C: a Box+scrim "dialog", BottomSheetScaffold/custom sheets, AnimatedVisibility overlays, Popup(focusable=false) (all same window). V: custom decor-view overlays, non-modal BottomSheetBehavior, custom drawers. NOT a bug: Compose Dialog, M3 ≥1.3 ModalBottomSheet, DialogFragment (own modal window; the one behind is removed from getWindows()). Static: a same-window overlay = a later-drawn subtree covering ≥X% of the window with paneTitle/dialog semantics/scrim geometry; unhidden stops under it are escape targets; a non-modal popup window is read after the main content. Dynamic: a walk starting inside the overlay steps into occluded nodes. Fix: a real Dialog/ModalBottomSheet, or hide the background; add a paneTitle.
- **tb.edge_stuck**: C: HorizontalPager (Role PAGER excluded from auto-scroll → the next page is unreachable by swipe); userScrollEnabled=false; drag-only. V: a custom LayoutManager without a11y scroll; ViewPager2 (pager); no TYPE_VIEW_SCROLLED (1s stall then skip). Static: content past the viewport (CollectionInfo count > visible; clipped children) but no direction SCROLL action or an excluded role. Dynamic: no VIEW_SCROLLED at the edge, or scrolled without progress. Fix: scroll semantics/actions, CollectionInfo, class name; page buttons/customActions for pagers.
- **tb.wrong_announcement**: C: a merged row reads children in PLACEMENT order ("$5, Title"); cd on a merging node + child text ("Profile, Jane, Jane"); clickable without Role; custom toggle without state; unchecked Checkbox without state (16.2). V: a container cd hides child state; labelFor wrong; custom View without role. Static: the model announcement with per-part provenance + R-rules. Dynamic: the TalkBack utterance from logcat when verbose, else the model announcement for the ACTUALLY focused node (utterance:"model"). Fix: clearAndSetSemantics{cd=…}, Role, stateDescription, toggleable, reorder composables.
- **tb.restore_failed**: single-activity nav (Fragments/Navigation Compose) with no window title/paneTitle change → no restore (only ENSURE → top); activity recreation (new window id); re-minted ids + scrolled away. Dynamic only: tb_scenario restore. Fix (as measured on TalkBack 17, part 5): explicit restoration, ACTION_ACCESSIBILITY_FOCUS on the row once it is laid out (View.performAccessibilityAction / the Compose host's node provider), with the list state kept (rememberSaveable/LazyListState, stable ids) so the row still exists; a paneTitle per destination and requestFocus do not restore.
- **tb.initial_focus**: the first stop is an unlabeled close X; an empty window title ("untitled"; Compose DialogProperties.windowTitle defaults to ""); a FocusRequester on a field pulls focus; requestInitialAccessibilityFocus is unsupported in Compose. Static: predict the initial-focus chain. Dynamic: tb_scenario focus_after. Fix: order/label; a window/pane title; drop stray focus requests.
- **tb.boundary_jump**: a View overlay sibling of a full-height ComposeView (STRIPE tie on top → "taller first" → the overlay is read AFTER all the Compose content); AndroidView content whose holder links are lost (a non-important interop root → the target isn't in TalkBack's tree); ComposeView cells with noHideDescendants; a Toolbar View vs a Compose top bar. Static: count facet switches inside one visual block; View subtrees placed far from their visual rank. Fix: overlay in the layout flow or linked via traversalBefore; isTraversalGroup around the AndroidView; make the interop root important.
- **tb.window_order**: a non-focusable PopupWindow/dropdown sorted after the main window by its top edge. Fix: a focusable/modal popup (ListPopupWindow modal).
- **tb.custom_action_missing**: C: SwipeToDismissBox/anchoredDraggable/pointerInput without customActions; combinedClickable without onLongClickLabel. V: ItemTouchHelper/OnTouchListener without ViewCompat.addAccessibilityAction. Static only (slot facet / listener introspection vs no labelled custom action). Fix: semantics{customActions} / addAccessibilityAction.
- **model.mismatch**: predicted ≠ walk. Reported separately as calibration data; ground truth wins.

## Part 3: Feature design (static model, payload, walk driver, diff)
### 3.1 host/inspector_widget/talkback/ (pure except device/inject/walk)
- rules.py: a literal port of the 16.2 predicates (shouldFocusNode, isSpeakingNode, hasNonActionableSpeakingChildren incl. the invisible-text rule, isTopLevelScrollItem, isActionableForAccessibility, Role.getRole, FILTER_AUTO_SCROLL, heading/control/container filters, isAutoScrollEdgeListItem). Every docstring cites file:line @229212f; TB_RULES_REV="talkback@229212f (16.2)" is echoed in outputs.
- tree.py: the "TalkBack view" projection of a DumpA11y. 1 drop non-important View nodes and hoist their children in place, via the new agent field `important`; without it a heuristic (AUTO + actionable/text/cd/liveRegion/pane/heading) at conf:"heuristic". 2 virtual (provider) nodes kept as-is (AS). 3 service-off corrections when the dump says a11y-services=off: mark AndroidView holder nodes invisible (the Compose chain is already primed by the agent). 4 window list (type, flags, frame, title, pane titles, which windows a modal window hides). 5 tag each node's host facet (view/compose/fake/interop).
- order.py: a literal port of OrderedTraversalController + WorkingTree + ReorderedChildrenIterator (+ NodeCachedBoundsCalculator) + searchFocus duplicate detection + the WindowTraversal geometric window sort/filter + edge/wrap. API simulate(tree, start=None, direction="next", granularity="default", max_steps=None) -> Order; reading_order(roots) returns the a11y.reading_order shape (the C7 adapter switches with one line).
- speech.py: the announcement composer (a TreeNodesDescription + RoleDescriptionExtractor port): STATE/NAME/ROLE order, cd suppresses children, fake Compose children, checkable/switch/edit/password/unlabelled/disabled/selected, collection position/transition, heading. parts:[{text, from: ref, kind: name|state|role|child|collection|window}].
- explain.py: reason codes. Stop: click, longclick, focusable, srf, scroll_item, text_orphan, leaf ("Unlabelled"), pip. Non-stop: hidden (alpha/visibility/clipped/hideFromAccessibility), not_important, hidden_by:<ref> (noHideDescendants/clearAndSet), window_wrapper, silent_container, merged_into:<ref>, no_speech, covered_by:<ref>, offscreen(+reachable:autoscroll|no). Edge: tree, bounds_swap, before:<ref>, after:<ref>, chain, window:<w>, autoscroll:<ref>, wrap.
- visual.py: heuristic XY-cut reading intent per window (blocks by the largest horizontal whitespace gap, top→bottom; columns by vertical gaps only when each has ≥2 stops, else a row; a11y containers kept contiguous); conf:"heuristic"; overridable by expect=[refs|labels].
- diff.py: align P (predicted), A (actual), V (visual) by LCS on ref (fallback: key, then label + IoU ≥0.8 for nodes first seen mid-walk); out_of_order = A (or P) stops outside the LIS of V-ranks + backward jumps; P≠A → model.mismatch diagnostics; findings on A when there's a walk, else P (basis:"walk"|"model").
- Source mapping: every finding carries capture refs; src File.kt:line from the capture index slot links (exact once slots are populated; otherwise next suggests capture(slots="enable") (destructive)); Views: #rid + the layout resource from View.getSourceLayoutResId() (public API 29).

### 3.3 Driving TalkBack
- REJECTED: `adb shell input keyevent|keycombination|swipe|tap`. Injected events SKIP the accessibility input filter (AOSP InputDispatcher::injectInputEvent never calls filterInputEvent; only notifyKey/notifyMotion do), so TalkBack never sees them. Worse, `input keycombination META_LEFT DPAD_LEFT` hits the system shortcut → BACK.
- DEFAULT: a uinput virtual keyboard. One long-lived `adb -s S shell uinput -` with a stdin pipe; register once with only modifier/arrow/Space/Enter/H/F/R keys (no KEY_Q → not "alphabetic" → no hardKeyboard config change, the IME stays). A step = updateTimeBase + inject [META↓ SYN, RIGHT↓ SYN, RIGHT↑ SYN, META↑ SYN] + sync (ack). Real kernel events → AccessibilityInputFilter → TalkBack onKeyEvent. Enhanced keymap: Meta+Right/Left next/prev; Meta+Ctrl+Left/Right first/last; Meta+Space click; Meta+Shift+Up/Down reading control; Meta+Up/Down move by reading control; browse mode = Meta double-press, then H/F (NewKeyComboModel:41,114,230-308,443,491).
- SAFETY (SV, KeyComboManager): never send Meta alone (lone Meta → "all apps/search" after 300ms, :1174); never send Meta+Left until Meta+Right has been seen to move focus (an unconsumed Meta+Left = system BACK); probe the keymap: Meta+Right, else Alt+Right (classic, older TalkBack); record keymap.
- FALLBACKS: emu (`adb -s emulator-5554 emu event send EV_KEY:KEY_LEFTMETA:1 …`, console kernel path) → sendevent (the emulator keyboard /dev/input/eventN; the shell is in group input; SELinux AS) → gesture (a uinput touchscreen, single-finger swipe right/left ~350px over 200ms, ≥12 samples; timing-sensitive but the exact user path) → model (no TalkBack; A11yAct ACCESSIBILITY_FOCUS to the model's next stop; "virtual, not ground truth"; for CI/no TalkBack; no recovery logic).
### 3.4 talkback_walk algorithm (walk.py)
1 device.ensure_on(): snapshot enabled_accessibility_services / accessibility_enabled / touch_exploration_enabled into <store>/talkback/<serial>.json BEFORE changes (crash-safe restore); APPEND the TalkBack component (preserve AccessibilityMenuService/Switch Access); wait for touch exploration = 1 and the agent reporting a11y-services=on (≤5s); if TrainingActivity is on top → KEYCODE_BACK (injected BACK reaches the activity, which is fine); re-foreground the app with am start only if needed (warn); a per-serial walk lock; captures record meta.a11y_services="talkback".
2 Capture (props off by default), model P (the Compose chain is live, not primed).
3 Start: start=ref → A11yAct(ACCESSIBILITY_FOCUS); "first" → Meta+Ctrl+Left; "current" (default). Read seq0.
4 Step: press the combo → A11yFocus(after_seq, wait_ms=1500, quiet_ms=150) (Compose batches events every 100ms, D:273); PANE/WINDOW events → extend to 700ms (TalkBack 550 + margin). Record {i, key→ref, bounds, speak (the model announcement at the ACTUAL node; the logcat utterance if enabled), dt_ms, via: next | autoscroll:<ref> (VIEW_SCROLLED from an ancestor scrollable during the step) | window:<w> | wrap | restore | stolen (an app VIEW_FOCUSED followed by a11y focus moving there)}. Unknown key (scrolled-in items) → recapture with carry-over (recapture="on_unknown", ≤1 per 3 steps).
5 Termination: no move within the timeout → an `edge` pause (reachEdge; the next press should wrap); two consecutive no-moves → stuck; the focused key == the first stop after an edge → wrap (default until); a key repeats with no edge/wrap in between → loop (record the cycle segment); focus outside app windows → left_app (IME/SystemUI); max_steps (default 60, max 300); timeout.
6 Restore settings unless leave_on=true (always in finally, at MCP atexit, and via `talkback restore`).
7 Diff A vs P, V (+ expect), classify, store <store>/walks/<wid>.json (+ capture ids), return.
Cost: ~150-350ms per plain step; 1-1.5s per auto-scroll step; 60 steps ≈ 15-25s (the spike measures it). Utterance source: logcat if TalkBack 17's developer "Log output level: Verbose" is settable (parse "Speaking fragment text="), else model (flagged per step).
### 3.5 Scenario engine (scenarios.py)
- focus_after(action, target?): actions activate (Meta+Space = TalkBack click on the focused node, the same path as a double-tap) | back (input keyevent BACK: a system action, same as TalkBack's back gesture) | tap (injected touch that bypasses TalkBack; labelled) | key:<combo>. Wait for window/pane events + 700ms, read focus, classify initial_ok (first content; the title is skipped when it equals the window title) | on_close_or_unlabeled | behind_overlay | stayed_on_opener | none.
- restore(target): focus target → activate → wait for the new screen → back → wait → read; classify restored (same ref/anchor) | near (same container) | top (first stop) | none; explain the WindowIdentifier inputs (root identity, title, pane titles) before/after.
- survive(target, mutate): focus target → mutation → sample the focus timeline for 2s (events + A11yFocus long-polls) → kept/drifted/restored/reset_top/lost. Mutations: tap:<sel> | activate | key:<combo> | broadcast:<am args> | probe:<action> (a new a11yprobe debug receiver: insert_top, shuffle, notify_all, change_item k). The cause comes from a before/after capture diff (rebound refs, key churn, removed nodes).
